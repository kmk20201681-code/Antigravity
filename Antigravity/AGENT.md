# DAMORI 홈페이지 레퍼런스 분석 작업 인계

## 문서 목적

이 문서는 다음 LLM 모델이 사용자와의 홈페이지 레퍼런스 분석 스킬 제작 작업을 중단 없이 이어가기 위한 현재 대화 요약이다.

기존 상세 인수인계는 `인수인계.md`에 있으며, 이 문서는 그 이후 사용자와 합의한 현재 진행 방향을 추가로 정리한다.

## 기본 소통 원칙

- 항상 한국어 존댓말로 답한다.
- 사용자가 정한 1~10단계의 순서와 의미를 임의로 바꾸지 않는다.
- 사용자의 확인 없이 단계를 완료했다고 선언하지 않는다.
- 새 규칙이나 방향이 생기면 먼저 정리해서 보여준다.
- 사용자가 `반영해줘`, `파일로 만들어줘`처럼 명시적으로 요청한 경우에만 관련 파일을 수정한다.
- 원본 리서치 자료와 기존 결과물을 수정하거나 덮어쓰지 않는다.
- 사용자가 직접 결정하기로 한 내용을 모델이 대신 확정하지 않는다.

## 프로젝트 목표

국내·해외 홈페이지 레퍼런스와 웹사이트 리서치 자료를 공통 기준으로 분류·비교하여 다음 내용을 도출하는 Codex 스킬을 제작한다.

- 디자인과 시각적 분위기
- 화면 및 콘텐츠 구성
- 사용자 흐름
- 문구와 콘텐츠 전달 방식
- 주요 기능
- 공통점과 차이점
- 반복 패턴과 특이 사례
- DAMORI 홈페이지에 적용할 인사이트

개발 중인 스킬 이름은 `homepage-reference-analyzer`이다.

## 전체 단계와 현재 상태

| 단계 | 내용 | 현재 상태 |
|---|---|---|
| 1 | 무엇을 분석할지 정하기 | 완료 |
| 2 | 어떤 자료를 넣을지 정하기 | 핵심 규칙 완료, 일부 실행 옵션 미정 |
| 3 | 원하는 결과물 정하기 | 완료 |
| 4 | 분류 기준 정하기 | 현재 진행 중 |
| 5 | 자료 하나를 정리하는 형식 만들기 | 보류 |
| 6 | 분석 방법 정하기 | 완료 |
| 7 | 스킬 폴더 만들기 | 완료 |
| 8 | `SKILL.md` 작성하기 | 완료 |
| 9 | 적은 자료로 시험하기 | 미진행 |
| 10 | 실제 사용하기 | 미진행 |

현재 사용자가 진행하려는 단계는 **4단계: 분류 기준 정하기**이다.

## 4단계에 대해 새로 확인된 사용자 의도

사용자는 지금까지 찾은 레퍼런스를 자신이 직접 특정 기준으로 비교·분류하려고 한다.

그 목적은 단순한 객관적 목록 작성이 아니라 다음과 같다.

1. 레퍼런스별 특징을 관찰한다.
2. 비슷한 레퍼런스를 그룹으로 묶는다.
3. 그룹과 레퍼런스 사이의 공통점과 차이점을 찾는다.
4. 자신이 선호하는 요소와 선호하지 않는 요소를 구분한다.
5. 이를 바탕으로 자신이 원하는 홈페이지의 느낌과 방향을 확립한다.
6. 정리한 결과를 모델에게 전달한다.
7. 모델은 전달받은 내용을 근거로 DAMORI의 디자인 방향과 공식 분류 기준을 구체화한다.

따라서 4단계에서는 모델이 사용자의 취향이나 DAMORI의 디자인 방향을 먼저 결정하면 안 된다. 사용자가 레퍼런스를 분석하고 선호 방향을 정리할 수 있도록 가이드와 양식을 제공하는 역할을 해야 한다.

## 사용자가 레퍼런스를 검토할 때 권장한 기준

각 레퍼런스를 다음 관점에서 살펴보도록 안내했다.

### 1. 전체 분위기

- 따뜻함
- 차분함
- 친근함
- 세련됨
- 전문적
- 고급스러움
- 감성적
- 실용적

분위기를 적을 때는 단어만 쓰지 말고 색상, 여백, 글자, 이미지 등 판단 근거를 함께 기록하도록 한다.

### 2. 색상

- 주요 색상과 보조 색상
- 밝기와 채도
- 배경색
- 강조색
- 마음에 드는 점
- 마음에 들지 않는 점

### 3. 타이포그래피

- 글꼴의 분위기
- 제목의 크기와 강조 방식
- 본문의 가독성
- 글자 굵기와 정보 위계
- 문장의 길이

### 4. 레이아웃

- 여백
- 정보 밀도
- 정렬 방식
- 콘텐츠 폭
- 카드형 또는 섹션형 구성
- 화면의 시각적 우선순위

### 5. 이미지와 그래픽

- 사진, 일러스트, 아이콘 또는 영상 사용
- 이미지의 분위기
- 인물, 공간, 제품 중 강조 대상
- 이미지가 차지하는 비중

### 6. 화면 구성

- 헤더와 내비게이션
- 첫 화면
- 주요 섹션
- 섹션 순서
- 문의 또는 행동 유도 영역
- 푸터

### 7. 사용자 흐름

- 첫 화면에서 먼저 확인하는 정보
- 핵심 행동까지의 이동 과정
- CTA의 종류와 위치
- 메뉴와 버튼의 편리성
- 흐름을 방해할 가능성이 있는 요소

### 8. 문구와 콘텐츠

- 메인 메시지
- 문구의 말투와 분위기
- 설명의 길이
- 서비스 설명 방식
- 신뢰를 주는 콘텐츠
- CTA 문구

### 9. 선호 판단

- 마음에 드는 점
- 마음에 들지 않는 점
- DAMORI에 가져오고 싶은 부분
- DAMORI에서는 피하고 싶은 부분

## 권장 비교 및 그룹화 방식

레퍼런스를 업종만으로 묶지 말고 **느낌과 표현 방식**이 비슷한 것끼리 그룹화하도록 안내했다.

그룹 예시는 다음과 같다.

- 따뜻하고 친근한 유형
- 차분하고 신뢰감 있는 유형
- 세련되고 고급스러운 유형
- 정보가 명확한 실용적 유형
- 개성이 강한 감성적 유형
- 기능과 행동을 강조한 유형

그룹마다 다음 내용을 기록한다.

```text
그룹 이름:
해당 레퍼런스:
공통점:
차이점:
전반적인 선호 여부:
선호하거나 선호하지 않는 이유:
DAMORI에 적용하고 싶은 요소:
```

## 선호 방향을 정리하는 네 가지 구분

사용자가 자신의 방향을 명확히 할 수 있도록 발견한 요소를 다음 네 종류로 나누도록 안내했다.

### 반드시 가져오고 싶은 요소

DAMORI에 꼭 적용하고 싶은 특징이다.

### 상황에 따라 사용하고 싶은 요소

필수는 아니지만 특정 화면이나 상황에 어울리면 적용할 특징이다.

### 피하고 싶은 요소

사용자가 원하지 않는 인상, 화면 구성 또는 표현 방식이다. 원하는 방향을 명확히 하는 핵심 자료이므로 반드시 기록하는 것이 좋다.

### 아직 판단하기 어려운 요소

추가 비교나 설명이 있어야 결정할 수 있는 항목이다. 모델이 임의로 결정하지 않는다.

## 원하는 느낌을 정리하는 문장 구조

사용자에게 최종 방향을 단어 나열이 아닌 다음 구조의 문장으로 정리하도록 안내했다.

```text
DAMORI는 [핵심 분위기]를 기본으로 하되,
[보완할 성격]을 함께 느낄 수 있어야 한다.
[원하는 표현 방식]으로 보여주며,
[피하고 싶은 인상]은 피한다.
```

예시:

```text
DAMORI는 따뜻하고 편안한 분위기를 기본으로 하되,
전문적이고 신뢰할 수 있는 느낌을 함께 전달해야 한다.
넓은 여백과 실제 사진, 간결한 문구를 사용하되
지나치게 감성적이거나 가벼워 보이는 표현은 피한다.
```

이 예시는 방향을 설명하기 위한 것이며 사용자의 확정된 취향이 아니다.

## 사용자가 모델에게 전달할 권장 결과 형식

```text
[레퍼런스 분류 결과]

1. 그룹별 분류
- 그룹 이름:
- 해당 레퍼런스:
- 공통점:
- 차이점:
- 선호 여부와 이유:

2. 전체적으로 반복되는 공통점
-

3. 주요 차이점
-

4. 반드시 가져오고 싶은 요소
-

5. 상황에 따라 사용할 요소
-

6. 피하고 싶은 요소
-

7. 아직 결정하지 못한 요소
-

8. 원하는 느낌을 정리한 문장
-

9. 요소별 핵심 참고 레퍼런스
- 색상:
- 타이포그래피:
- 레이아웃:
- 첫 화면:
- 콘텐츠:
- 사용자 흐름:
```

## 사용자의 결과를 받은 뒤 모델이 해야 할 일

사용자가 레퍼런스 분류 결과와 원하는 느낌을 전달하면 다음 순서로 처리한다.

1. 사용자의 표현을 임의로 바꾸지 않고 먼저 구조화한다.
2. 서로 비슷한 요구를 통합한다.
3. 서로 충돌하는 요구가 있는지 찾는다.
4. 모호한 표현에는 관찰 가능한 디자인 근거를 연결한다.
5. 핵심 디자인 키워드를 도출한다.
6. DAMORI에 가져올 요소와 피할 요소를 구분한다.
7. 레퍼런스별 역할을 정리한다.
   - 색상 참고
   - 타이포그래피 참고
   - 레이아웃 참고
   - 화면 구성 참고
   - 콘텐츠 참고
   - 사용자 흐름 참고
8. 이를 기반으로 4단계의 공식 분류 기준 초안을 제안한다.
9. 사용자에게 확인받은 뒤에만 4단계 완료 여부를 확정한다.
10. 사용자가 명시적으로 반영을 요청한 경우에만 기존 설계 문서나 `SKILL.md`를 수정한다.

## 아직 하면 안 되는 작업

현재는 다음 작업을 진행하지 않는다.

- 사용자의 레퍼런스 분석 결과를 받기 전에 4단계를 임의로 완료 처리
- 5단계 상세 기록 양식 확정
- 실제 전체 홈페이지 분석
- 외부 URL 직접 조사
- 캡처 이미지 분석
- 스킬 공식 설치
- `PyYAML` 설치
- 원본 리서치 자료 수정
- 기존 결과 파일 덮어쓰기

## 관련 파일

- `인수인계.md`: 기존 전체 작업 내역과 확정 규칙
- `리서치/homepage-reference-analyzer/SKILL.md`: 개발 중인 스킬 본문
- `리서치/[리서치 결과]_DAMORI_국내_UIUX_레퍼런스_v1.txt`: 국내 기본 자료
- `리서치/[리서치 결과]_DAMORI_해외_UIUX_레퍼런스_v1.txt`: 해외 기본 자료
- `AGENTS.md`: 저장소 작업 지침

## 다음 모델이 시작할 위치

현재 사용자는 레퍼런스를 직접 비교·분류하고 자신이 원하는 느낌을 확립하려는 상태다.

다음 모델은 사용자가 정리한 내용을 보내면 즉시 분석하되, 보내기 전이라면 먼저 결과를 기다리거나 사용자가 요청한 특정 부분의 분류를 돕는다. 사용자의 취향을 추측하거나 DAMORI의 방향을 선제적으로 확정하지 않는다.

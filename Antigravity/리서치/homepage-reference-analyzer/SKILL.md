# Homepage Reference Analyzer

## 목적

홈페이지 레퍼런스 자료를 근거 중심으로 통합하고 비교하여 새 홈페이지 제작에 활용할 수 있는 인사이트를 만든다. 기본 자료와 추가 자료를 구분하고, 사실·해석·추정을 분리하며, 모든 결론을 원문 출처로 추적할 수 있게 한다.

## 실행 전 확인

분석을 시작하기 전에 다음 미결정 항목을 확인한다. 사용자가 이미 정한 항목은 다시 묻지 않는다.

- 결과를 저장할 폴더와 세부 파일 이름
- 추가 자료를 현재 분석에서만 사용할지 계속 저장할지
- 자료에 포함된 URL을 직접 열어 현재 홈페이지까지 조사할지
- 캡처 이미지를 함께 분석할지
- 홈페이지별 점수와 분석 항목별 중요도를 사용할지
- 기본 자료로 허용할 파일 확장자

미결정 항목을 임의로 확정하지 않는다. 필요한 결정만 한 번에 하나씩 구체적으로 질문하고, 사용자의 답을 받은 뒤 진행한다.

## 기본 자료 찾기

1. 현재 작업 공간에서 사용자가 지정한 `리서치` 폴더를 찾는다.
2. 폴더 바로 아래의 파일 중 파일명에 리터럴 문자열 `[리서치 결과]`가 포함된 파일을 모두 찾는다.
3. 대괄호를 와일드카드 패턴으로 해석하지 말고 파일명 문자열에 포함됐는지 직접 비교한다.
4. 사용자가 허용한 확장자와 UTF-8 읽기 조건을 만족하는 파일만 기본 자료로 등록한다.
5. 기본 자료의 원문, 파일명, 위치와 내용을 수정하거나 덮어쓰지 않는다.
6. 조건을 만족하는 파일이 여러 개이면 모두 사용한다.
7. 조건을 만족하는 파일이 없으면 임의의 파일을 대신 사용하지 말고 사용자에게 알린 뒤 중단한다.
8. 읽을 수 없거나 UTF-8로 해석할 수 없는 파일은 숨기지 말고 파일명과 실패 이유를 보고한다.

각 기본 자료에 다음 출처 정보를 부여한다.

- 자료 구분: `기본 자료`
- 원본 파일명
- 원본 파일 위치
- 자료 안의 홈페이지 이름과 URL

## 추가 자료 받기

사용자가 정확히 `리서치 자료 추가 입력`이라고 명령하면 이후에 제공하는 파일, URL 또는 직접 입력한 텍스트를 추가 자료로 인식한다.

1. 실제 추가 자료가 제공될 때까지 임의의 내용을 만들거나 분석을 시작하지 않는다.
2. 추가 자료를 `추가 자료`로 표시하고 기본 자료와 분리하여 출처를 기록한다.
3. 추가 자료로 기본 자료의 파일이나 내용을 덮어쓰지 않는다.
4. 사용자가 지속 저장을 명시하지 않으면 추가 자료를 현재 분석 범위에서만 사용한다.
5. URL 직접 조사가 허용되지 않았다면 URL 자체를 출처로만 보존하고 현재 페이지 내용을 추측하지 않는다.
6. 사용자가 분석 시작 또는 추가 입력 완료 의사를 밝히면 기본 자료와 추가 자료를 함께 분석한다.

추가 자료에 다음 출처 정보를 부여한다.

- 자료 구분: `추가 자료`
- 입력 형태: 파일, URL 또는 직접 입력 텍스트
- 파일명 또는 URL
- 제공된 대화 위치나 식별 가능한 입력 순서

## 자료 목록 만들기

모든 자료에서 홈페이지별로 다음 정보를 추출한다.

- 홈페이지 또는 서비스 이름
- URL
- 업종 또는 분야
- 기본 자료와 추가 자료 구분
- 발견된 모든 원문 출처

자료에 없는 값은 임의로 보충하지 말고 `확인되지 않음`으로 표시한다.

## 중복 홈페이지 통합하기

1. 홈페이지 이름, 서비스 이름, URL의 호스트와 경로를 함께 비교한다.
2. 동일한 서비스의 동일한 홈페이지라고 판단되는 항목을 하나의 분석 대상으로 통합한다.
3. 추적 파라미터, URL 끝의 슬래시와 단순 표기 차이는 중복 판단에서 제외하되 원본 URL은 모두 보존한다.
4. 같은 서비스라도 목적이 다른 별도 페이지를 무조건 하나로 합치지 않는다.
5. 중복 여부가 불확실하면 합치지 말고 `중복 가능성 확인 필요`로 표시한다.
6. 통합된 홈페이지는 분석 결과 1개로 계산한다.
7. 통합 후에도 발견된 기본 자료와 추가 자료의 출처를 모두 남긴다.

## 홈페이지별 개별 분석

각 홈페이지를 다음 상위 항목으로 분석한다.

1. 기본 정보
   - 홈페이지 이름
   - URL
   - 업종
   - 자료 출처
2. 디자인
3. 화면 구성
4. 사용자 흐름
5. 문구와 콘텐츠
6. 주요 기능
7. 장점과 단점
8. 참고할 부분

분류 기준과 홈페이지별 세부 기록 형식이 별도 참고 파일로 확정되면 그 기준을 우선 적용한다. 확정 전에는 위 상위 항목만 사용하고 세부 기준을 임의로 확장하지 않는다.

자료에 기록된 내용과 URL 직접 조사에서 새로 확인한 내용을 구분한다. 확인할 수 없는 디자인, 기능이나 사용자 흐름은 추측하지 말고 `추가 조사 필요`로 표시한다.

## 유사 요소 그룹화하기

1. 여러 홈페이지에서 의미가 비슷한 요소를 하나의 대표 그룹으로 묶는다.
2. 표현은 다르지만 목적과 행동이 같은 요소는 동일한 그룹으로 정규화한다.
3. 대표 그룹 이름과 원래 표현을 함께 보존한다.
4. 같은 홈페이지에서 동일한 요소가 여러 번 나타나도 등장 횟수는 1회로 계산한다.

예:

```text
상담 신청 버튼
문의하기 버튼
무료 상담 버튼
→ 문의 유도 버튼
```

## 등장 횟수와 비율 계산하기

각 그룹에 대해 다음 값을 기록한다.

- 발견된 홈페이지 수
- 확인 가능한 전체 홈페이지 수
- 비율
- 해당 요소를 확인할 수 없어 계산에서 제외한 홈페이지 수

비율은 다음과 같이 계산한다.

```text
발견된 홈페이지 수 ÷ 해당 요소를 확인할 수 있는 홈페이지 수 × 100
```

같은 홈페이지를 한 그룹에서 두 번 이상 세지 않는다. 계산의 분모와 제외 수를 함께 표시한다.

## 패턴 구분하기

다음 기준으로 패턴을 구분한다.

- 공통 패턴: 확인 가능한 홈페이지 중 30% 이상
- 반복 패턴: 10% 이상 30% 미만
- 특이 사례: 10% 미만이지만 참고 가치가 있는 사례

등장 횟수만으로 가치와 중요도를 단정하지 않는다. 적게 사용됐더라도 활용 가치가 높은 아이디어는 특이 사례로 별도 기록한다.

특이 사례에는 다음 내용을 포함한다.

- 독특한 점
- 활용할 수 있는 상황
- 적용할 때 주의할 점
- 근거가 된 홈페이지와 출처

## 전체 비교 분석하기

다음 관점으로 홈페이지를 비교한다.

- 대부분 사용하는 방식
- 업종에 따라 달라지는 방식
- 서로 반대되는 방식
- 특정 홈페이지에서만 사용하는 방식
- 반복되는 디자인과 화면 구성
- 자주 사용되는 문구와 콘텐츠 방식
- 공통 기능
- 사용자 경험상 좋은 사례
- 사용자 경험상 불편할 수 있는 사례

업종과 목적이 다른 홈페이지를 무조건 같은 기준으로 평가하지 않는다. 차이가 발생한 맥락과 적용 가능한 상황을 함께 분석한다.

각 패턴을 다음 내용으로 설명한다.

- 패턴
- 등장 횟수와 비율
- 사용한 홈페이지
- 확인된 사실
- 분석
- 장점
- 단점
- 어울리는 상황
- 주의할 점
- 자료 출처

## 최종 인사이트 만들기

인사이트를 다음 세 종류로 구분한다.

- 반드시 참고할 공통 방식
- 상황에 따라 선택할 방식
- 차별화를 위해 참고할 독특한 방식

각 인사이트에 다음 내용을 포함한다.

- 인사이트 내용
- 판단 근거
- 관련 홈페이지
- 자료 출처
- 새 홈페이지에 적용할 아이디어
- 적용 가능한 상황
- 적용할 때 주의할 점

자료만으로 판단하기 어려운 내용은 다음 형식으로 표시한다.

```text
추가 조사 필요:
확인할 내용:
현재 부족한 근거:
확인 방법:
```

## 분석 작성 원칙

- 원문에 있는 사실과 분석자의 해석을 분리한다.
- 중요한 결론과 인사이트에 반드시 출처를 연결한다.
- 기본 자료와 추가 자료의 출처를 구분한다.
- 확인할 수 없는 내용을 사실처럼 작성하지 않는다.
- 근거가 부족한 판단은 `추정` 또는 `추가 조사 필요`로 표시한다.
- 단순 요약에서 끝내지 말고 공통점, 차이점과 반복 패턴을 찾는다.
- 새 홈페이지 제작에 실제로 활용할 수 있는 제안을 작성한다.
- 자료에 없는 내용을 임의로 만들어내지 않는다.

## 결과 파일 만들기

결과는 한글과 URL이 깨지지 않도록 모두 UTF-8 인코딩의 `.txt` 파일로 만든다.

다음 결과를 각각 별도 파일로 분리한다.

1. 홈페이지별 분석
2. 전체 비교 분석
3. 최종 인사이트

홈페이지별 분석 파일에는 다음 규칙을 적용한다.

- 홈페이지 하나를 분석 결과 1개로 계산한다.
- TXT 파일 하나에 최대 100개의 홈페이지를 기록한다.
- 100개를 초과하면 `001-100`, `101-200`과 같이 100개 단위 범위로 분할한다.
- 홈페이지 하나의 분석 내용을 두 파일로 나누지 않는다.
- 분할된 파일에서도 홈페이지 번호를 연속으로 유지한다.

전체 비교 분석은 모든 홈페이지별 분석이 끝난 후 한 번만 작성한다. 최종 인사이트는 전체 비교 분석과 분리하여 별도 파일로 만든다.

사용자가 결과 폴더와 세부 파일 이름을 정하지 않았다면 저장하기 전에 확인한다. 기본 자료와 기존 결과 파일을 덮어쓰지 않는다.

## 결과 검사하기

저장 전에 다음 내용을 검사한다.

- 조건을 만족하는 기본 자료를 모두 사용했는가
- 추가 자료를 기본 자료와 구분했는가
- 중복 홈페이지를 통합하고 모든 출처를 보존했는가
- 홈페이지별 필수 상위 분석 항목이 누락되지 않았는가
- 등장 횟수와 비율의 분모가 명시됐는가
- 사실, 분석과 추정을 구분했는가
- 모든 중요 결론에 근거와 출처가 연결됐는가
- TXT 파일 하나에 홈페이지가 100개를 초과하지 않는가
- 홈페이지 하나가 두 파일로 나뉘지 않았는가
- 결과가 UTF-8 TXT로 저장됐는가
- 기본 자료와 기존 결과를 덮어쓰지 않았는가

검사에 실패하면 결과를 완료했다고 보고하지 말고 실패 항목을 먼저 수정하거나 사용자에게 알린다.

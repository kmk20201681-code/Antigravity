# 홈페이지 레퍼런스 분석 스킬 인수인계

## 1. 작업 목표

여러 홈페이지 레퍼런스와 웹사이트 리서치 자료를 분류·비교하여 디자인, 화면 구성, 사용자 흐름, 문구·콘텐츠, 기능 패턴과 새 홈페이지 제작에 활용할 인사이트를 만드는 Codex 스킬을 제작하고 있다.

스킬 이름은 `homepage-reference-analyzer`이며 현재 개발용 폴더에 `SKILL.md`까지 작성된 상태다. 아직 공식 검증, 설치와 실제 분석은 진행하지 않았다.

## 2. 사용자와 작업할 때 지킬 방식

- 항상 한국어 존댓말을 사용한다.
- 사용자가 정한 1~10단계의 순서와 내용을 임의로 변경하지 않는다.
- 한 단계에서 필요한 결정을 구체적으로 설명하고, 사용자가 입력할 수 있는 문장 예시를 함께 제공한다.
- 사용자의 직접 입력이나 확인 전에는 단계를 완료했다고 선언하지 않는다.
- 새 규칙이나 설정이 나오면 먼저 정리해서 보여주고, 기존 설계 파일에 반영할지 질문한다.
- 사용자가 `반영해줘`처럼 명확하게 지시한 경우에만 설계 파일이나 스킬 파일을 수정한다.
- 외부에서 가져온 예시의 프로젝트명과 파일명을 실제 작업 파일로 판단하지 않는다.
- 사용자가 제공한 예시에서는 파일명이 아니라 작업 방식과 규칙만 현재 DAMORI 자료에 접목한다.
- 원본 리서치 자료와 기존 결과를 덮어쓰지 않는다.

## 3. 단계별 진행 상태

| 단계 | 내용 | 상태 |
|---|---|---|
| 1 | 무엇을 분석할지 정하기 | 완료: 웹사이트 레퍼런스 & 웹사이트 리서치 |
| 2 | 어떤 자료를 넣을지 정하기 | 핵심 규칙 설정 완료, 일부 실행 옵션 미정 |
| 3 | 원하는 결과물 정하기 | 완료 및 설계 초안 반영 |
| 4 | 분류 기준 정하기 | 사용자 요청으로 보류 |
| 5 | 자료 하나를 정리하는 형식 만들기 | 사용자 요청으로 보류 |
| 6 | 분석 방법 정하기 | 완료 및 설계 초안·SKILL.md 반영 |
| 7 | 스킬 폴더 만들기 | 완료 |
| 8 | SKILL.md 작성하기 | 완료 |
| 9 | 적은 자료로 시험하기 | 미진행 |
| 10 | 실제 사용하기 | 미진행 |

4·5단계는 사용자가 나중에 직접 진행하겠다고 했으므로 먼저 작성하거나 임의로 확정하지 않는다.

## 4. 확정된 입력 규칙

### 기본 자료

- `리서치` 폴더 바로 아래에서 파일명에 리터럴 문자열 `[리서치 결과]`가 포함된 파일을 찾는다.
- 해당 조건을 만족하는 파일이 여러 개면 모두 기본 자료로 사용한다.
- 대괄호를 와일드카드로 해석하지 말고 파일명 문자열로 비교한다.
- 기본 자료의 원문, 파일명과 내용을 수정하거나 덮어쓰지 않는다.
- 조건에 맞는 파일이 없으면 임의의 파일을 사용하지 말고 사용자에게 알린다.

### 추가 자료

- 정확한 명령어는 `리서치 자료 추가 입력`이다.
- 이 명령 이후 제공되는 파일, URL 또는 직접 입력 텍스트를 추가 자료로 인식한다.
- 추가 자료는 기본 자료를 덮어쓰지 않는다.
- 기본 자료와 추가 자료의 출처를 구분해 기록한다.
- 같은 홈페이지가 중복되면 하나의 분석 대상으로 통합하지만 발견된 모든 출처는 보존한다.
- 분석할 때 기본 자료와 추가 자료를 함께 사용한다.

## 5. 확정된 분석 방법

1. 홈페이지별로 디자인, 화면 구성, 사용자 흐름, 문구와 콘텐츠, 주요 기능, 장단점과 참고할 부분을 분석한다.
2. 의미가 비슷한 요소를 대표 그룹으로 묶는다.
3. 같은 홈페이지의 동일 요소는 한 번만 계산한다.
4. 등장 홈페이지 수, 확인 가능한 전체 수, 비율과 제외 수를 기록한다.
5. 패턴을 다음과 같이 구분한다.
   - 공통 패턴: 30% 이상
   - 반복 패턴: 10% 이상 30% 미만
   - 특이 사례: 10% 미만이지만 참고 가치가 있는 사례
6. 대부분 사용하는 방식, 업종별 차이, 서로 반대되는 방식과 특정 홈페이지만의 방식을 비교한다.
7. 최종 인사이트를 반드시 참고할 공통 방식, 상황에 따라 선택할 방식, 차별화를 위한 독특한 방식으로 구분한다.
8. 사실, 분석과 추정을 구분하고 중요한 결론에는 출처를 연결한다.
9. 확인할 수 없는 내용은 `추정` 또는 `추가 조사 필요`로 표시한다.

세부 분류 기준은 4단계, 홈페이지별 상세 기록 형식은 5단계에서 추후 확정한다.

## 6. 확정된 결과 규칙

- 모든 분석 결과는 UTF-8 `.txt` 파일로 생성한다.
- 홈페이지 하나를 분석 결과 1개로 계산한다.
- 홈페이지별 분석, 전체 비교 분석과 최종 인사이트를 각각 별도 파일로 만든다.
- 홈페이지별 분석 TXT 하나에는 최대 100개를 기록한다.
- 100개를 초과하면 `001-100`, `101-200`처럼 분할한다.
- 홈페이지 하나의 분석 내용을 두 파일로 나누지 않는다.
- 전체 비교 분석은 모든 홈페이지별 분석 후 한 번만 작성한다.
- 기존 결과 파일을 덮어쓰지 않는다.

결과 내용은 다음과 같이 구성한다.

- 홈페이지 기본 정보: 이름, URL, 업종
- 홈페이지별 분석: 디자인, 화면 구성, 사용자 흐름, 문구·콘텐츠, 주요 기능, 장단점, 참고할 부분
- 전체 비교 분석: 공통점, 차이점, 반복 패턴, 눈에 띄는 사례
- 최종 인사이트: 적용 아이디어, 우선 참고할 홈페이지, 주의점, 추가 조사 내용

## 7. 현재 파일 구조

```text
Antigravity/
├─ AGENTS.md
├─ 명령어규칙.txt
├─ 홈페이지 레퍼런스 분석 스킬 예상 내용.txt
├─ 인수인계.md
└─ 리서치/
   ├─ [리서치 결과]_DAMORI_국내_UIUX_레퍼런스_v1.txt
   ├─ [리서치 결과]_DAMORI_해외_UIUX_레퍼런스_v1.txt
   └─ homepage-reference-analyzer/
      ├─ SKILL.md
      ├─ agents/
      │  └─ openai.yaml
      └─ references/
```

`references/`는 4·5단계가 보류되어 현재 비어 있다.

## 8. 검증된 현재 상태

- 실제 기본 자료 두 파일은 모두 `리서치` 폴더 바로 아래에 있다.
- 두 파일명 모두 `[리서치 결과]` 조건을 만족한다.
- 두 파일 모두 엄격한 UTF-8 읽기에 성공했다.
- 국내 자료와 해외 자료에 URL이 각각 3개씩 있다.
- 총 6개 URL은 절대 HTTP/HTTPS URL 형식이며 중복 URL은 없다.
- `SKILL.md`는 UTF-8, 259줄, TODO 0개다.
- `SKILL.md`의 YAML 앞부분에 `name`과 `description`이 존재한다.
- `agents/openai.yaml`은 생성되어 있으나 UI 문구는 현재 영어다.
- 스킬은 `C:\Users\SBS\.codex\skills`에 설치되지 않았다. 현재 위치는 개발용이므로 자동 발견되지 않을 수 있다.
- 공식 `quick_validate.py`는 현재 Python 환경에 `PyYAML`이 없어 `ModuleNotFoundError: No module named 'yaml'`로 실행되지 않았다.
- `PyYAML` 설치나 외부 스킬 폴더 설치는 아직 하지 않았다.

## 9. 무시해야 하는 예시 파일명

`홈페이지 레퍼런스 분석 스킬 예상 내용.txt`의 마지막 부분에는 다음 외부 예시 파일명이 남아 있다.

- `SEUMIM_신규_웹사이트_기획_레퍼런스_34선.txt`
- `SEUMIM_웹사이트_기획_레퍼런스_200선.txt`

이 파일들은 사용자의 실제 파일이 아니다. 존재 여부를 검사하거나 필수 자료로 요구하지 않는다. 현재 실제 자료는 `[리서치 결과]_DAMORI_...` 두 파일이다. 사용자는 SEUMIM 예시에서 작업 방식만 가져와 현재 파일에 접목하라고 명확히 지시했다.

설계 초안에서 이 예시 문구를 제거하거나 수정하려면 먼저 사용자에게 반영 여부를 묻는다.

## 10. 아직 결정하지 않은 내용

- 추가 자료를 현재 분석에서만 사용할지 계속 저장할지
- 결과물을 저장할 폴더와 세부 파일 이름
- 홈페이지별 점수 평가 사용 여부
- 분석 항목별 중요도 기준
- TXT의 URL을 직접 열어 현재 홈페이지를 추가 조사할지
- 캡처 이미지를 함께 분석할지
- 기본 자료로 허용할 파일 확장자

이 항목을 임의로 정하지 말고 실제 실행 전에 사용자에게 필요한 결정만 하나씩 구체적으로 질문한다.

## 11. 다음 권장 작업

사용자의 다음 명령을 기다린다. 진행 요청이 오면 다음 순서가 안전하다.

1. 파일을 수정하지 않고 스킬 기본 검증을 수행한다.
2. 공식 검증에 필요한 `PyYAML` 설치가 필요하면 먼저 승인을 요청한다.
3. 미결정 실행 조건 중 시험에 꼭 필요한 항목만 확인한다.
4. 현재 기본 자료에서 홈페이지 3~5개로 시험한다.
5. 출처, 중복 통합, 패턴 계산, UTF-8 출력과 원본 보호를 확인한다.
6. 시험 통과 후에만 Codex 기본 스킬 폴더 설치와 전체 분석을 진행한다.

사용자가 명령하기 전에는 4·5단계 작성, 실제 분석, 스킬 설치, 외부 URL 조사나 원본 자료 변경을 진행하지 않는다.
